# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности: товар и покупатель. Для их типизации используются следующие интерфейсы.

### Интерфейс IProduct
Описывает структуру одного товара, получаемого с сервера и используемого в приложении.

Поля интерфейса:
`id: string` - уникальный идентификатор товара.
`description: string` - текстовое описание товара.
`image: string` - ссылка на изображение товара.
`title: string` - название товара.
`category: string` - категория товара.
`price: number | null` - стоимость товара. Может быть `null`, если товар не имеет стоимости.

Интерфейс используется в моделях данных для хранения и обработки информации о товарах.

### Интерфейс IBuyer
Описывает структуру данных покупателя при оформлении заказа.

Поля интерфейса:
`payment: TPayment | null` - выбранный способ оплаты. Значение null означает, что способ оплаты ещё не выбран.
`email: string` - электронная почта покупателя.
`phone: string` - контактный телефон покупателя.
`address: string` - адрес доставки.

Интерфейс используется для хранения и валидации данных покупателя.

## Модели данных

Раздел описывает классы, реализующие хранение и обработку данных приложения. Каждый класс хранит данные определённой сущности и предоставляет методы для работы с ними.

### Класс ProductCatalog
Отвечает за хранение и управление списком товаров, доступных в приложении.

Конструктор:
`constructor(protected events: IEvents)` - принимает экземпляр брокера событий `EventEmitter`, который используется для генерации событий при изменении данных каталога.

Поля класса:
`_products: IProduct[]` - хранит массив всех товаров, загруженных в приложение.
`_selectedProduct: IProduct | null` - хранит товар, выбранный для подробного отображения.

Методы класса:
`setProducts(products: IProduct[]): void` - сохраняет переданный список товаров в каталоге.
`getProducts(): IProduct[]` - возвращает массив всех товаров.
`getProductByID(id: string): IProduct | undefined` - возвращает товар по его идентификатору.
`setSelectedProduct(product: IProduct): void` - сохраняет товар для подробного отображения.
`getSelectedProduct(): IProduct | null` - возвращает выбранный товар или `null`, если товар не установлен.

### Класс Cart
Отвечает за хранение и управление товарами, выбранными пользователем для покупки.

Конструктор:
`constructor(protected events: IEvents)` - принимает экземпляр брокера событий `EventEmitter`, который используется для генерации событий при изменении данных корзины.

Поля класса:
`_items: IProduct[]` - хранит массив товаров, добавленных пользователем в корзину.

Методы класса:
`getItems(): IProduct[]` - возвращает массив товаров, находящихся в корзине.
`addItem(product: IProduct): void` - добавляет товар в корзину.
`removeItem(id: string): void` - удаляет товар из корзины.
`clear(): void` - удаляет из корзины все товары.
`getTotalPrice(): number` - возвращает общую стоимость товаров в корзине.
`getItemsCount(): number` - возврашает количество товаров в корзине.
`hasItem(id: string): boolean` - проверяет наличие товара в корзине по его id.

### Класс Buyer
Отвечает за хранение, обновление и валидацию данных покупателя при оформлении заказа.

Конструктор:
`constructor(protected events: IEvents)` - принимает экземпляр брокера событий `EventEmitter`, который используется для генерации событий при изменении данных покупателя.

Поля класса:
`_payment: TPayment | null` - хранит выбранный способ оплаты.
`_email: string` - хранит электронную почту покупателя.
`_phone: string` - хранит контактный телефон покупателя.
`_address: string` - хранит адрес доставки.

Методы класса:
`setData(data: Partial<IBuyer>): void` - сохраняет данные покупателя. Позволяет обновлять отдельные поля, не удаляя уже сохранённые значения других полей.
`getData(): IBuyer` - возвращает все данные покупателя.
`clear(): void` - очищает данные покупателя.
`validate(): Partial<Record<keyof IBuyer, string>>` - выполняет валидацию данных. Поле валидно, если оно не пустое. Возвращает объект с ошибками, где ключи соответствуют полям покупателя, а значения - текст ошибки.

## Слой представления (View)

Отвечает за отображение пользовательского интерфейса приложения.
Компоненты View получают данные от презентера, отображают их в DOM и генерируют события при действиях пользователя.

### Базовый класс Component
Базовый класс для всех компонентов представления. Содержит общий функционал для работы с DOM-элементами.

Конструктор:
`constructor(protected readonly container: HTMLElement)` - принимает корневой DOM-элемент компонента и сохраняет его в защищённом свойстве класса. Данный элемент используется как основной контейнер, в котором компонент отображает данные.

Поля класса:
`container: HTMLElement` - защищённое свойство, содержащее корневой DOM-элемент компонента. Используется в наследуемых классах для доступа к DOM и обновления интерфейса.

Методы класса:
`render(data?: Partial<T>): HTMLElement` - основной метод отображения компонента. Принимает объект данных, которые необходимо отобразить в интерфейсе.
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - вспомогательный метод для установки изображения в переданный элемент `<img>`.

## События приложения

В проекте используется событийно-ориентированный подход.
Компоненты представления и другие слои генерируют события, которые обрабатываются презентером. Это позволяет разделить ответственность между слоями приложения и избежать жёсткой связи между компонентами.

### События представления
`basket:open` - генерируется при нажатии на кнопку корзины в шапке сайта. Используется для открытия модального окна корзины.
`basket:delete` — генерируется при нажатии на кнопку удаления товара в карточке корзины. Используется для удаления выбранного товара из корзины.
`basket:order` — генерируется при нажатии на кнопку «Оформить» в корзине. Используется для открытия формы оформления заказа.
`modal:close` - генерируется при закрытии модального окна. Используется для скрытия модального окна.
`success:close` - генерируется при нажатии на кнопку закрытия в окне успешного оформления заказа. Используется для закрытия модального окна с подтверждением заказа.
`cart:toggle` - генерируется при нажатии на кнопку добавления или удаления товара в карточке подробного просмотра.
`form:change` - генерируется при изменении любого поля формы. В объекте события передаются имя поля и его новое значение. Используется для обновления данных покупателя в модели.
`order:submit` - генерируется при отправке формы выбора способа оплаты и адреса доставки. Используется для перехода к следующему шагу оформления заказа.
`contacts:submit` - генерируется при отправке формы контактных данных. Используется для финальной отправки заказа на сервер.
`product:select` — генерируется при нажатии на карточку товара в каталоге. Используется для выбора товара для просмотра.

### События моделей данных
`buyer:changed` - генерируется при изменении данных покупателя или очистке данных.
`cart:changed` - генерируется при изменении содержимого корзины: добавлении товара, удалении товара или очистке корзины.
`products:changed` - генерируется при сохранении списка товаров в модель каталога.
`product:selected` - генерируется при выборе товара для подробного отображения.


## Презентер
В проекте презентер реализован в основном файле `main.ts`.
Он выступает посредником между слоями Model и View, связывая данные приложения с пользовательским интерфейсом.
Он подписывается на события, генерируемые моделями данных и компонентами представления, и выполняет соответствующие действия: изменяет состояние моделей или обновляет отображение интерфейса.

Презентер не хранит данные приложения. Все данные хранятся в моделях, а представления отвечают только за отображение информации в интерфейсе.

### Основные задачи презентера

#### Загрузка каталога товаров
После запуска приложения презентер выполняет запрос к серверу для получения списка товаров через класс `WebLarekApi`. Полученный массив товаров передаётся в модель `ProductCatalog`. После сохранения данных модель генерирует событие `products:changed`, которое обрабатывается презентером. В обработчике этого события создаются карточки товаров `CardCatalog` и передаются в компонент `Gallery` для отображения каталога на главной странице.

#### Просмотр товара
При нажатии на карточку товара компонент `CardCatalog` генерирует событие `product:select`. Презентер получает идентификатор выбранного товара, находит соответствующий объект в модели `ProductCatalog` и сохраняет его как выбранный. После этого модель генерирует событие `product:selected`, в обработчике которого презентер создаёт карточку предпросмотра `CardPreview` и открывает модальное окно с подробной информацией о товаре.

#### Добавление и удаление товаров из корзины
При нажатии на кнопку в карточке предпросмотра генерируется событие `cart:toggle`. Презентер проверяет, находится ли товар в корзине:
- если товар уже добавлен, он удаляется из корзины;
- если товара нет в корзине, он добавляется.

После изменения содержимого корзины модель `Cart` генерирует событие `cart:changed`, в обработчике которого презентер обновляет счётчик товаров в шапке страницы.

#### Работа с корзиной
При нажатии на кнопку корзины генерируется событие `basket:open`. Презентер получает список товаров из модели `Cart`, создаёт карточки товаров `CardBasket` и отображает их в компоненте `Basket`. Затем открывается модальное окно корзины.

При удалении товара из корзины генерируется событие `basket:delete`, после чего товар удаляется из модели корзины и список товаров обновляется.

#### Оформление заказа
При нажатии на кнопку «Оформить» в корзине генерируется событие `basket:order`. Презентер открывает форму оформления заказа `OrderForm`, в которой пользователь выбирает способ оплаты и вводит адрес доставки.

При изменении данных формы генерируется событие `form:change`. Презентер сохраняет изменённые данные в модели Buyer и выполняет валидацию данных.

После отправки первой формы генерируется событие `order:submit`, и презентер открывает вторую форму `ContactsForm` для ввода контактных данных пользователя.

После отправки формы контактов генерируется событие `contacts:submit`. Презентер собирает данные заказа из моделей `Cart` и `Buyer`, формирует объект заказа и отправляет его на сервер через `WebLarekApi`.

#### Успешное оформление заказа
После успешной отправки заказа:
- корзина очищается;
- данные покупателя сбрасываются;
- отображается окно подтверждения заказа `OrderSuccess`.

#### Закрытие модальных окон
Презентер обрабатывает события `modal:close` и `success:close`, после чего вызывает метод закрытия модального окна.
